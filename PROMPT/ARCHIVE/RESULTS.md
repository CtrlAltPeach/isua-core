# ИСУА — Результаты работы

> **ИСУА** — Информационная система учёта абитуриентов
> Прототип интерфейса для приёмной комиссии вуза

---

## Описание проекта

Веб-приложение для учёта поступающих в вуз абитуриентов. Позволяет операторам приёмной комиссии вести базу данных абитуриентов, отслеживать статусы заявок, анализировать конкурсную ситуацию по образовательным программам и экспортировать данные.

Реализовано **5 интерактивных экранов** (+авторизация), полностью покрывающих ключевые сценарии работы приёмной комиссии. **Вторая итерация** добавляет аутентификацию, истории изменений, усложнённую валидацию экзаменов и миграцию на PostgreSQL.

### Почему этот стек

- **Next.js 16** — единый фреймворк для frontend + API, SSR/CSR на выбор
- **Prisma + PostgreSQL** — типобезопасный ORM, масштабируемость для продакшена, миграции
- **shadcn/ui** — готовые доступные компоненты, кастомизируемые через Tailwind
- **Zustand** — простое глобальное состояние без бойлерплейта Redux
- **TanStack Table** — headless-таблица с сортировкой, фильтрацией, пагинацией из коробки
- **Recharts** — декларативные графики, интеграция с shadcn/ui ChartContainer
- **bcrypt + JWT** — стандартная аутентификация без зависимостей от внешних сервисов
- **Zod** — runtime validation для API-запросов, типобезопасность на границах системы

## Реализованные экраны

### 0. Авторизация (новое!)

**Страницы:**
- `/login` — вход в систему (email + пароль)
- `/register` — регистрация нового оператора (username, email, пароль)

Обе страницы защищены — если пользователь уже авторизован, редирект на `/`.

### 1. Дашборд (`/` — вкладка «Дашборд»)

Агрегированная ежедневная статистика приёмной кампании.

| Элемент | Описание |
|---------|----------|
| **4 карточки метрик** | Всего абитуриентов, Новые заявки (applied), Согласили (consentToEnroll), Документы собраны |
| **BarChart** | Абитуриенты vs бюджетные места по программам |
| **PieChart** | Распределение по статусам: applied / withdrawn (donut) |
| **Таблица конкурса** | Программа / Места / Абитуриенты / Конкурс (цветовая индикация) |
| **Круговой прогресс** | Процент собранных документов |
| **Прогресс-бары** | Доля каждого статуса |

Карточки кликабельны — ведут на список с соответствующим фильтром.

### 2. Список абитуриентов (вкладка «Абитуриенты»)

Полнофункциональная таблица данных с историей изменений.

| Функция | Детали |
|---------|--------|
| **Поиск** | По ФИО / телефону / email, debounce 300мс |
| **Фильтры** | По статусу (applied / withdrawn) и по программе (5) |
| **Сортировка** | По ФИО, программе, статусу, баллам (totalScore), дате |
| **Пагинация** | 25 / 50 / 100 на страницу, номера страниц |
| **Добавление** | Кнопка «Добавить» → модальный диалог |
| **Редактирование** | Клик по строке или кнопка меню → форма с вкладками |
| **История** | Просмотр всех изменений (кто, что, когда, старое → новое значение) |
| **Удаление** | Подтверждение + toast-уведомление |
| **Экспорт** | Кнопка «CSV» → скачивание файла |

**Вкладки в форме редактирования:**
1. **Основное** — ФИО, программа, статусы (applied/withdrawn, consentToEnroll)
2. **Баллы** — 6 экзаменов (mathBase 2-5, остальные 0-100), автовычисляемый totalScore
3. **Контакты** — телефон, email
4. **Персональные** — адрес, INN, SNILS, примечания
5. **История** — журнал изменений

### 3. По программам (вкладка «Программы»)

Карточки образовательных программ с аналитикой.

Каждая карточка содержит:
- Название программы и бюджетных мест
- Прогресс-бар заполненности
- Конкурс (чел./место) с цветовой индикацией
- Разбивка по статусам (applied / withdrawn)
- Топ-3 абитуриентов по totalScore
- Кнопка «Все абитуриенты» → переход на список с фильтром

### 4. По статусам (вкладка «Статусы»)

Kanban-доска с 2 колонками (изменено!).

| Колонка | Цвет | Статус |
|---------|------|--------|
| Подали заявление | emerald | `applied` |
| Отозвали | rose | `withdrawn` |

Внутри — прокручиваемые мини-карточки (ФИО, программа, totalScore, документы, согласие). Клик → редактирование в модале.

## API-маршруты

### Авторизация (новое!)
| Метод | Маршрут | Назначение |
|-------|---------|-----------|
| `POST` | `/api/auth/register` | Регистрация пользователя (email, username, password) |
| `POST` | `/api/auth/login` | Вход в систему (возвращает JWT в cookie) |
| `POST` | `/api/auth/logout` | Выход из системы (очистка cookie) |
| `GET` | `/api/auth/me` | Получение текущего пользователя (требует авторизации) |

### Абитуриенты (основное)
| Метод | Маршрут | Назначение |
|-------|---------|-----------|
| `GET` | `/api/applicants` | Список с фильтрами, поиском, пагинацией, сортировкой |
| `POST` | `/api/applicants` | Создание нового абитуриента |
| `GET` | `/api/applicants/[id]` | Получение одного абитуриента |
| `PUT` | `/api/applicants/[id]` | Обновление (с оптимистичной блокировкой via `version`) |
| `DELETE` | `/api/applicants/[id]` | Удаление |
| `GET` | `/api/applicants/[id]/history` | История изменений абитуриента (новое!) |

### Программы
| Метод | Маршрут | Назначение |
|-------|---------|-----------|
| `GET` | `/api/programs` | Список программ с количеством абитуриентов |
| `POST` | `/api/programs` | Создание программы |

### Статистика (изменено!)
| Метод | Маршрут | Назначение |
|-------|---------|-----------|
| `GET` | `/api/stats/daily` | Ежедневная статистика (было `/api/stats`) |

**Итого: 13 endpoints** (было 8). Оптимистичная блокировка: при `PUT` передаётся `version`. Если версия не совпадает → `409 Conflict`.
