## Приоритет 1 — Инфраструктура БД

### 1.1. Пересоздать БД с ICU/русской локалью
**Проблема:** текущий кластер создан с `--locale=C`, из-за чего нативный `ILIKE`/сортировка
не учитывают регистр кириллицы. Сейчас обойдено в поиске через `lower(... COLLATE "und-x-icu")`,
но это костыль в raw SQL.

**Что сделать:**
- `initdb` заново с ICU-провайдером и локалью `ru-RU` (или `und-x-icu`).
- Убрать ICU-COLLATE из raw-запроса поиска → вернуть обычный Prisma `mode: "insensitive"`.
- Пере-seed данных.

## Приоритет 2 — Завершить фазу 4 (вкладки + история)

### 2.1. Вкладка «Программы» (карточки)
- Карточка на программу: места, абитуриенты, конкурс, средний балл, прогресс-бар заполненности,
  разбивка по статусам, топ-3 по баллам, кнопка «Все абитуриенты» (→ список с фильтром).
- Данные: `/api/programs` + `/api/stats/daily` (или новый endpoint топ-N).

### 2.2. Вкладка «Статусы» (Kanban)
- 2 колонки: «Подал заявление» (зелёная), «Забрал заявление» (красная).
- Мини-карточки: ФИО, программа, балл, документы/согласие, кнопка редактирования.
- (Опционально) drag-and-drop смены статуса.

### 2.3. Модальное окно истории изменений
- Кнопка-часы в строке таблицы → модалка с журналом (`/api/applicants/[id]/history`).
- Колонки: поле, старое→новое, кто, когда (в выбранной таймзоне).
- Добавить кнопку истории обратно в таблицу (сейчас в действиях только edit/delete).

## Приоритет 4 — Фаза 5: синхронизация (real-time)

> Механизм выбрать в начале фазы: REST-локи+polling vs Socket.io. Схема `Lock` в БД готова.

- API блокировок: `POST/DELETE /api/locks/[id]`, `POST .../heartbeat`.
- Heartbeat каждые 10 сек, таймаут 30 сек → авто-снятие.
- UI: при открытии записи — lock; показывать «Редактирует: …»; снятие при закрытии.
- (Если Socket.io) кастомный server.js + broadcast lock/unlock/update.
