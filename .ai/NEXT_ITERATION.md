## Итерация 16: Ротация ключа шифрования (M3)

Проблема: сейчас один `ENCRYPTION_KEY`; при его смене все ранее зашифрованные ПДн
(`enc:v1:iv:tag:ct`, поля passport/inn/snils) становятся нечитаемыми — `decrypt()`
ловит ошибку GCM и возвращает `null` (`lib/crypto.ts`). Цель: безопасная смена ключа
без потери данных.

### План (порядок)
1. **Keyring в `lib/crypto.ts`:**
   - `ENCRYPTION_KEY` — текущий (им шифруем новое).
   - `ENCRYPTION_KEY_OLD` — прежний ключ(и) на время ротации (можно список через запятую).
   - `decrypt`: пробуем текущий ключ; при ошибке GCM — поочерёдно старые (auth-tag GCM
     однозначно отличает верный ключ); все не подошли → `null`.
   - `encrypt`: всегда текущим ключом. Формат остаётся `enc:v1` (trial-decrypt не требует
     смены формата; kid-тег `enc:v2:<kid>` — опционально, если захотим отслеживать прогресс).
2. **Конфиг:** задокументировать `ENCRYPTION_KEY` + `ENCRYPTION_KEY_OLD` в `.env.example`
   (и в Vercel env на время ротации).
3. **Скрипт ре-шифрования** (`npm run crypto:rotate`): пройти всех абитуриентов, для каждого
   ПДн-поля `decrypt` (keyring) → `encrypt` (текущий ключ) → `update`. Идемпотентно, батчами,
   с логом счётчика. Запускается с обоими ключами в env.
4. **Runbook ротации** (в `ops/DATABASE_ENVIRONMENTS.md` или `SECURITY.md`): OLD=старый,
   ENCRYPTION_KEY=новый → деплой → прогон скрипта на прод-БД → проверка → убрать OLD.
5. **Тесты** (`crypto.test.ts`): keyring decrypt (новый+старый), ре-шифрование делает
   значение читаемым только новым ключом, неверный ключ → `null`.
6. **Доки:** `SECURITY.md` (M3 → закрыто), `CHANGELOG`, `CONTEXT` (формат/ключи), `.env.example`.

Оценка: ~полдня. Затрагивает `crypto.ts`, `crypto.test.ts`, `.env.example`, новый скрипт +
запись в `package.json`, доки.
